Recovery kit

A backup can only be opened with its key. In production, backup files and the recovery kit (that key plus the key for saved integration credentials) are not downloadable from this page, so a stolen admin session cannot take them. Get the kit on the command line and keep it in a password manager, away from the backups:

Azure: deploy/azure/deploy.sh ... --kit-out recovery-kit.json

VM: sudo grcpal backup kit --out /backups/recovery-kit.json

To allow downloads here again, set GRCPAL_WEB_BACKUP_DOWNLOAD=on; every download is then emailed to all admins. Details: docs/operations.md, "Recovery kit".

Restore

{% if data.can_restore %}

To go back to a backup on this server, open Restore this backup under it in the list above.

{% endif %}

To rebuild on a clean machine, install GRC-pal, copy a backup file and your recovery kit to the server, and run:

grcpal backup restore FILE.grcbak --kit recovery-kit.json

Restore checks the whole file first and only fills an empty instance or a new folder, so it can never overwrite data. Everyone signs in again afterwards with their existing accounts. Details: docs/operations.md, "Restore".
