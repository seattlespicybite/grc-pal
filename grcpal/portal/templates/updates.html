{% elif data.deployment == 'azure' %}

Updates on Azure

This instance runs GRC-pal {{ data.version }}. Updates run from your program repository's GRC-pal update workflow (Actions tab), not from this page, so the portal itself can never change its own software.

  • Nothing installs on its own. The workflow checks every Monday and lists newer releases in its run summary; an update installs only when someone runs the workflow with the version number.
  • Every update takes a backup first and tries the new version on a copy of the data. The new version then runs beside the current one with no users, and must pass its checks before it takes over. The workflow log shows each step with its percentage.
  • The previous version stays ready (and pre-update backups are kept at least 30 days): run the workflow with rollback to go back.

Each update, failed trial and rollback appears in the audit log (update.applied, update.trial_failed, update.rolled_back). Details: docs/deploy-azure.md, "Updates".

{% else %}

Manual installation

This copy of GRC-pal was not installed with the VM installer, so updates are manual: take a backup, install the new version, start it. Migrations run on start and refuse data they cannot read.

For automatic, checked updates with rollback, use the VM installer (docs/deploy-vm.md).
